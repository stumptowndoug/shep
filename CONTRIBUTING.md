# Contributing to Shep

Thanks for taking the time to help improve Shep.

## Start with an issue

Public issues are the primary contribution channel. Before proposing code:

1. Search existing issues for the same problem or idea.
2. Open a bug report or feature request with the relevant context.
3. Wait for a maintainer to confirm that the change fits the product direction
   and agree on a narrow scope and approach.

Please do not begin a substantial implementation with the expectation that it
will be merged before that discussion happens.

## Pull requests are by invitation

Pull request creation is restricted to repository collaborators. A maintainer
may invite or coordinate with a contributor after an issue has a clear,
agreed-upon implementation plan.

An invitation applies only to the agreed issue and scope. It is not blanket
approval for unrelated changes.

## Keep changes reviewable

- Address one concern per pull request.
- Link the agreed issue and explain the user-visible outcome.
- Avoid drive-by cleanup, broad architectural rewrites, and unrelated features.
- Do not add generated or mechanical changes unless the issue requires them.
- Keep the commit history focused and remove exploratory or fixup commits before
  requesting review.
- Include appropriate tests and describe the validation you performed.

A maintainer may close a pull request that was not requested, has moved beyond
the agreed scope, or is too broad to review safely. Closing a pull request is a
scope decision, not a judgment about the contributor or the effort involved.
